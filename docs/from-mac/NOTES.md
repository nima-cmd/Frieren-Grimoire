# Hardware notes

## Razer BlackWidow Elite (1532:0228): confirmed working settings

Verified with `razer_test.py` on 2026-10-16 (macOS 15 / Darwin 24.6, hidapi 0.15.0).

| Setting | Value |
|---|---|
| HID interface | **0** (usage page 0x01, usage 0x06) |
| Transaction ID | **0x1F** (matches OpenRazer for 0x0228) |
| Report | 90 bytes, feature report ID 0 (send 91 bytes including the ID) |
| Response | Read back with get-feature-report ID 0; status byte 0x02 = OK |

HID interfaces the keyboard exposes:

- 0: keyboard (0x01/0x06). Lighting control works here.
- 1: keyboard, consumer control, system control, and a vendor collection.
- 2: mouse (0x01/0x02) and pointer (0x01/0x01).

### macOS gotcha: open the device non-exclusively
hidapi on macOS opens devices with `kIOHIDOptionsTypeSeizeDevice` by default, and
that fails on a keyboard the system is using ("open failed"). Call
`hid_darwin_set_open_exclusive(0)` after `hid_init()`. In Swift/IOKit, call
`IOHIDDeviceOpen(device, IOOptionBits(kIOHIDOptionsTypeNone))`. Sending feature
reports also needs Input Monitoring (see below).

### OpenRazer reference (driver/razerkbd_driver.c)
- All matrix effects for the Elite (none, static, breathing, spectrum, wave,
  reactive, starlight, brightness, custom frame) use transaction ID 0x1F.
- The game-mode LED uses transaction ID 0xFF.
- Effects use the "extended matrix" commands (class 0x0F) in razerchromacommon.c.

## macOS app setup (milestone 2)

- **Input Monitoring is required.** Opening the keyboard's HID interface fails with
  `kIOReturnNotPermitted` until FrierenRazer is allowed under System Settings →
  Privacy & Security → Input Monitoring. The app requests it, shows a notice, and
  re-applies the color once it's granted. (Python worked without this only because
  the parent app already had the permission.)
- **Sign with a stable identity.** Ad-hoc signing ties the permission to one build's
  hash, so every rebuild loses it. The project signs with the free Personal Team
  (`DEVELOPMENT_TEAM = 498NSJSCM7`, "Apple Development"), which keeps the grant
  across rebuilds.
- If the grant gets stuck on a stale entry (tccd logs `status: -67050`), run
  `tccutil reset ListenEvent local.FrierenRazer` and grant it again.
- The certificate needs Apple's **WWDR G3** intermediate in the login keychain
  (https://www.apple.com/certificateauthority/AppleWWDRCAG3.cer); without it the
  identity shows as invalid.

## Per-key colors (milestone 4)

- Matrix is 6 rows × 22 columns. Each row is uploaded with class 0x0F id 0x03
  (data size 0x47, args `00 00 row start stop RGB…`), then the custom effect
  (class 0x0F id 0x02, args `00 00 08`, data size 0x0C) shows it. All use
  transaction ID 0x1F. Verified key-for-key on the keyboard.
- The key layout (`RazerKit/Sources/RazerKit/BlackWidowEliteLayout.swift`) is
  generated by `tools/extract_layout.py` from Polychromatic's
  `data/devicemaps/blackwidow_elite_en_US.svg` (GPLv3), where each key's id is
  `x<column>-y<row>`. Media keys are placed over the numpad columns by hand.
- Row 0 col 21 is the volume dial ring, row 5 col 11 the logo under the spacebar.

## Mac mode

- On macOS the Windows key already sends ⌘, but sits where ⌥ is on a Mac
  keyboard. Mac mode swaps them with `hidutil property --matching
  '{"VendorID":5426,"ProductID":552}' --set '{"UserKeyMapping":[…]}'`:
  Win→⌥, Alt→⌘, right Alt→⌘, Menu→⌥. It affects only this keyboard.
- hidutil mappings don't survive a replug or reboot, so the app re-applies them
  on every connect. To clear by hand: run the same command with `"UserKeyMapping":[]`.
- Game Mode (which disables the Win key) can be read with class 0x03 id 0x80,
  args `01 08`, transaction ID 0xFF.

## Profiles (milestone 5)

- Stored in `~/Library/Application Support/FrierenRazer/profiles.json`
  (`{ activeID, profiles: [{ id, name, lighting }] }`), written 0.5 s after the last
  edit and on quit. Settings from before profiles are migrated into "Default".
- Lighting and Mac mode are re-applied on launch, on keyboard connect, and 2 s
  after `NSWorkspace.didWakeNotification` / `screensDidWakeNotification`.
- Open at Login uses `SMAppService.mainApp`.

## Key remaps (milestone 6)

- Each layout key carries its HID usage, converted from Polychromatic's
  `blackwidow_elite.json` (Linux keycodes) with the kernel's hid-input.c table.
  Polychromatic lists Delete as keycode 114 (volume down); the generator fixes it to 0x4C.
  Regenerate with:
  `python3 tools/extract_layout.py blackwidow_elite_en_US.svg blackwidow_elite.json > RazerKit/Sources/RazerKit/BlackWidowEliteLayout.swift`
- Remaps are per profile, merged over Mac mode (a remap of the same key wins),
  and applied with the same hidutil call. fn, media keys, dial and logo are
  handled in firmware and can't be remapped.

## Macros and per-app profiles (milestone 6)

- Macros live in `profiles.json` (`macros`), shared by all profiles; each can be
  limited to app bundle IDs. Trigger = virtual key code + ⌘⌥⌃⇧, as seen after
  hidutil remaps (so with Mac mode, Alt is ⌘).
- A `CGEvent` tap (session, head insert) swallows the trigger's key-down/up and
  runs the actions: type text (Unicode, Return for newlines), press shortcut,
  open app, open URL, wait. Posted events carry `eventSourceUserData` 0x46524945
  so the tap skips them, and use explicit flags so held trigger modifiers don't leak.
- Needs **Accessibility** (System Settings → Privacy & Security → Accessibility).
  The tap starts only when an enabled macro has a trigger and actions, and is
  re-enabled if macOS times it out. It can't tell which keyboard a key came from.
- Per-app profiles: `appProfiles` maps bundle ID → profile. On
  `didActivateApplicationNotification` the app's profile overrides the one you
  picked (not saved); FrierenRazer's own windows are ignored, so you can edit it.
- An unreadable `profiles.json` is moved to `profiles-unreadable-<date>.json`
  instead of being overwritten.

## Key & mouse bindings with G-Shift

- Each profile has `bindings`: a normal and a G-Shift layer mapping inputs
  (Razer key by HID usage, or a G Pro mouse slot) to an action: another key,
  a spell, a shortcut, or disabled. One input can be the G-Shift button (hold it
  for the second layer). Older `remaps` migrate into the normal layer.
- `BindingCompiler` splits them: normal-layer key→key goes to hidutil (Razer
  only). Normal-layer spells/shortcuts/disabled keys and a keyboard G-Shift key
  are routed through spare codes F16–F20 (PrtSc/ScrLk/Pause already arrive as
  F13–F15) so only the Razer's key triggers them; the event tap acts on them.
  G-Shift-layer keys match whatever the key sends after the normal layer.
- Mouse slots are learned (press the button) because what they send depends on
  G HUB. Defaults: wheel = button 2, left side = Back (3) / Forward (4); the right
  pair mirrors the left until G HUB gives it distinct keystrokes. DPI and
  G HUB-only functions never reach macOS. Works with G HUB running.
- Edited in the Spellbook (Keyboard & Mouse) or the key editor's Actions tab.

## Sound

- Core Audio: default output/input switching (also the alert device), volume,
  mute, mic level; follows changes made elsewhere.
- The Nari Ultimate dongle shows up as "Razer Nari Ultimate - Game" and
  "- Chat" (1532:051A). Neither has software volume; the headset wheel and mic
  mute act inside the headset and send nothing to the Mac.
- Haptic intensity, logo LED and battery use feature report 0xFF on interface 5
  (usage page 0xFF00). The format is public; see docs/nari-protocol.md. The app
  sends haptics (on/off, 0–100) and logo on/off only when changed, re-sends them
  when the headset comes back or the Mac wakes, and reads battery every minute.
  Verified on the headset. Pairing frames are never sent.

## Installing

- Run `tools/install.sh`: builds Release and installs /Applications/FrierenRazer.app.
  Use that copy day to day. Accessibility kept resetting for rebuilt Debug
  copies in build/DerivedData, but survives reinstalls in /Applications.
  If a grant gets stuck: `tccutil reset Accessibility local.FrierenRazer`, then grant again.

## Mac mode protection

- While Mac mode is on, Control, Shift, Option, Command (both sides) and Menu
  keep their modifier role: their normal-layer bindings and G-Shift use are
  ignored (with a note in the editor) and can't be set. Their G-Shift-layer
  actions still work.
